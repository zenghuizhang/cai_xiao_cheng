## 3. 数据模型规范

### 3.1 词条命名规范（解决命名体系分裂的根因）

- `term` = **口语名**（用户会搜/会点到的词），如「通胀」「定期存款」
- `aliases` = **正式名**（如「通货膨胀」）及同义词（「均价成本」「摊薄成本」）
- 匹配逻辑（现有 `matches` 已支持）：term 或 aliases 包含匹配
- **强制约束**：卡片 `glossary_terms` 中的每个词必须命中至少一个词条的 term 或 aliases —— 由校验脚本 + 单元测试强制

### 3.2 卡片字段（沿用现有）

`id / chapter / order_index / title / daily_analogy / core_knowledge / illustration_note / glossary_terms / points / difficulty / related_quiz_id`

- 新卡 `glossary_terms` 只允许引用词条库已有词条
- 新卡优先配新题（`related_quiz_id`），配不了的不留空——用同章已有题目兜底

### 3.3 版本机制

- 批 1（词条对齐 + 卡片 80→100）：`content_version` 4 → 5
- 批 2（卡片 100→120 + 书籍/每日题/模拟）：5 → 6
- 每批结束跑全部测试 + 发布门禁，可独立出包

## 4. 质量门禁（每批交付必须全绿）

```
□ 交叉引用测试（新增）：卡片→词条 100% 可查；无孤儿词条（未达 1 次引用）
□ 结构测试（已有 + 扩展）：ID 唯一、答案索引合法、模拟选项数=3、字段齐全
□ 文本质量：one_line ≤20 字、类比/正文非空、无 TODO/占位符
□ 数量达标：卡片≥100→120、每章题=8、每日题≥45、书籍≥16、模拟=8
□ 发布文档：README「内容规模」一节同步更新
```

## 5. 内容风格规范（生成新内容时遵守）

- **口语化第一**：小白能读，类比优先（奶茶店/买菜/开餐馆）
- **字数**：daily_analogy 80~120 字；core_knowledge 100~150 字；one_line ≤20 字；daily_analogy（词条）30~50 字
- **合规红线**：不荐股、不承诺收益、不出现具体代码/股票名、收益率为假设示例、标注「不构成投资建议」
- **与现有内容不重复**：新增话题不得与已有 80 张卡主题撞车（框架文档已做缺口分析）
